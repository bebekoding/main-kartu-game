# Card data and HTML rendering

Implemented 27 October 2026, following the host and membership fixes.

- All 118 dynamic HTML write sites in the application use `setSafeHTML`, backed by
  `GameDisplay.setHTML`. DOMPurify returns a DOM fragment inserted without reparsing.
- Executable markup, event attributes, embedded documents, SVG/MathML and external
  images are excluded. Dynamic images may only use the local J/Q/K/joker filenames.
  CSS resource loads and unrecognized CSS functions are rejected; existing local
  colors, typography and layout styles remain supported.
- Card renderers validate the 13 ranks, four suits and two joker colors before
  creating markup. A malformed legacy card becomes an inert `?` placeholder.
- Tebak status/log ranks, counts and four-of-a-kind labels are escaped. Remi combo
  attributes use a fixed enum rather than interpolating a database value.
- RTDB validates cards in Truf hands/bids/tricks, Remi hands/deck/discards/combos,
  Cangkul hands/pile/tricks, and Tebak hands/deck/sets/actions/logs. Parent writes,
  partial field writes, room creation and atomic updates cannot bypass validation.
- Legitimate Remi pickup metadata and legacy discard/Tebak set representations
  remain supported. Joker cards are accepted only in Remi/Cangkul card locations.
- No existing room, account, card or score is rewritten by this release.

DOMPurify 3.4.17 is pinned in `package-lock.json`. The browser build is vendored from
the matching official npm package, with its license, so clients do not depend on a
new third-party CDN. After any dependency update, copy the matching `dist/purify.min.js`
and `LICENSE` to `vendor/dompurify`, update the script version, and rerun the tests.

Sources: [official DOMPurify repository](https://github.com/cure53/DOMPurify) and
[security threat model](https://github.com/cure53/DOMPurify/wiki/Security-Goals-%26-Threat-Model).

## Verification

```sh
npm ci
npm test
npm run check:render
node scripts/build-room-rules.cjs
npm run test:rules
```

`test:rules` requires the official Database emulator on `127.0.0.1:19000`; it only
writes disposable demo namespaces. Run it sequentially because both suites load
rules and replace their isolated fixture database.

26 Node tests and 45 emulator tests pass, including the 48 existing host tests.
The Node tests render all 216 cards generated by the actual four deck functions,
check every local image filename, dispatch hostile event payloads, exercise the
actual Remi/Tebak renderers, and check all inline scripts for unfiltered HTML APIs.
Browser preview uses dummy players with no production account or database writes.

This release addresses audit finding A04. Card privacy, administrator authorization,
chat/signal identity and authoritative gameplay/leaderboards remain separate work.
